# 视觉还原协议 v2

> 本文件是本 skill 的唯一规范来源。规则只有三种落地方式：**代码强制**、**测试守护**、**人工步骤**。
> 没有第四种。任何规则若三样都没有，视为无效规则，删掉。
> 第 12 节是自洽性对照表，逐条声明每条规则由谁执行。

---

## 1. 两种参考形态，证据强度不同

| 形态 | 定义 | 可获得的证据 | 不可获得 |
|---|---|---|---|
| **图源** | 只有一张图（设计稿导出、截图） | E1 像素、E2 几何（靠图像取证） | E3 样式、E4 行为、真实换行点 |
| **页源** | 参考可渲染（本地页面或公开页面） | E1–E4 全部 | —— |

图源模式永远拿不到样式证据，因此：
- 图源模式下**禁止**声称"样式一致"，只能声称"像素与几何接近"；
- 图源模式下最终判决不得为 `READY`，只能 `READY WITH SUBSTITUTIONS` 或 `UNVERIFIED`；
- 这是硬约束，由判决函数强制（见第 3 节末）。

**图源模式的取证要求**：参考侧没有 DOM，几何配对无法运行，所以必须先用图像取证得到可比较的数字——扫色带定行高与分隔线、扫像素簇定列位、取色定组件颜色与底色。工具：`image-spec.mjs`（CLI）+ `probe/image-spec.mjs`（纯函数分析，可单测）。

没有这步，比对退化为肉眼比对，收敛会停在 5% 量级。实测：页面源模式可追到 0.136%；图源模式缺取证时停在 5.28%，工具到位后一轮降到 4.88%。

**图源模式的继承性豁免**：无法自动判定，必须人工声明并附图像证据，命令为 `--inherit "检查项:证据"`。判决话术区分"自动判定"与"人工声明，须附证据"两种来源。

## 2. 证据等级

任何结论必须声明它站在哪一级证据上。跨级声称视为无效。

| 等级 | 内容 | 获取方式 |
|---|---|---|
| **E1 像素** | 截图逐像素差异、热区、归因 | 渲染 + canvas 比对 |
| **E2 几何** | 元素盒的位置与尺寸；文字墨水包围盒 | 两侧各量一遍，按角色配对 |
| **E3 样式** | computed style：字号、行高、字重、字距、色值、圆角、边框、内边距、间距 | 仅页源可获取 |
| **E4 行为** | 状态、交互、动效、断点插值 | 仅页源或可操作实现 |
| **E5 真机** | 触屏、真实字体渲染、设备像素比 | 实机运行 |

规则：
- 只说"接近"不够，必须给出该判断所依据的等级与数值；
- 没有 E1 就不得下视觉结论；
- 没有 E3 就不得下样式结论；
- 没有 E5 就必须列入未验证项，不许含糊。

## 3. 判决：两个维度分开判，再合成

视觉与规范是两个独立维度。**它们的失败原因不同，处置也不同**，混在一个词里必然失真。

### 3.1 视觉维

输入：像素差异占比、最大通道差、几何漂移数、文本集中度。

| 状态 | 条件 |
|---|---|
| **通过** | 像素差异 ≤ 容差，且几何漂移 = 0 |
| **边际** | 像素差异在容差与实质阈值之间，几何漂移 = 0 |
| **不通过** | 像素差异 > 实质阈值，或几何漂移 > 0 |

**关键几何漂移的定义**：任一配对项的 x、y、宽、高任一项偏移超过漂移容差（默认 1px），即计入。当前不做权重区分——所有漂移同等对待，先严格后放宽；将来若要区分，必须先改本节再改代码。

默认容差：像素 0.5%、实质阈值 2%、单点通道差 32、几何漂移 1px、文本集中度 3 倍。
阈值可配置（`--material`），但**必须随报告一起输出实际使用的值**，且放宽原因要写进交接。

### 3.2 规范维

输入：检查项结果（按设备上下文过滤后）、继承性豁免。

| 状态 | 条件 |
|---|---|
| **通过** | 所有适用的必检项通过（豁免项不计） |
| **不通过** | 任一适用的必检项失败 |

### 3.3 合成

| 视觉 | 规范 | 最终判决 |
|---|---|---|
| 通过 | 通过 | `READY` |
| 边际 | 通过 | `READY WITH SUBSTITUTIONS` |
| 通过 / 边际 | 通过（但有豁免或替代项） | `READY WITH SUBSTITUTIONS` |
| 不通过（仅像素超标、集中在文本区、几何零漂移、已声明地板证据） | 通过 | `READY WITH DECLARED FLOOR` |
| 不通过 | 任意 | `NOT READY` |
| 任意 | 不通过 | `NOT READY` |
| 缺证据 / 环境不稳 / 图源模式下声称样式一致 | —— | `UNVERIFIED` |

**优先级**：证据缺失 > 环境不稳 > 维度失败 > 替代项。缺证据永远压过一切，不许用干净的数字掩盖没跑过的检查。

## 4. 继承性豁免

参考稿自身存在的违规，不该由实现承担。这是最常见的一种误判：忠实还原一个 12.5px 输入框，被判成失败。

规则：
1. 豁免只对"参考稿同样存在"的违规生效，且**必须在同一设备上下文下测得**；
2. 图源模式无法自动判定，必须人工声明并附图像证据；
3. 豁免必须写入替代清单，格式：`继承：<检查项> — <证据>`；
4. 参考稿中不存在的违规，一律不得豁免；
5. 豁免不降低最终判决为 `READY`，只能到 `READY WITH SUBSTITUTIONS`——因为这是"照抄了一个有问题的设计"，不是"做对了"。

## 5. 检查项目录

每条检查必须满足三件事，否则不得入库：**有判定代码、有反例样本、声明设备上下文**。

| id | 设备上下文 | 判定 | 反例样本 |
|---|---|---|---|
| `no-emoji` | 全部 | 渲染文本中不得出现 `Extended_Pictographic` | 含 🚀 ✅ 的页面 |
| `no-default-purple-gradient` | 全部 | 不得出现色相 250–290、两端高饱和的渐变 | `linear-gradient(135deg,#6366f1,#8b5cf6)` |
| `input-font-16` | 触屏 | 输入类控件字号 ≥ 16px | 13px 输入框 |
| `tap-target-44` | 触屏 | 可点元素 ≥ 44×44 | 40×24 按钮 |
| `no-h-overflow` | 全部 | 文档不产生横向滚动 | 1600px 内容塞进 1280px |
| `icons-are-svg` | 全部 | ≤32px 的图标不得是位图 | png 图标 |
| `no-placeholder-copy` | 全部 | 不得出现占位文案 | lorem ipsum、example.com |
| `no-pill-pile` | 全部 | 大圆角容器不得连续成堆 | 5 个 radius ≥16 的块 |

设备上下文规则：
- `desktop` 只启用"全部"项；
- `touch` 启用"全部"+"触屏"项；
- 上下文由任务声明，不由实现自己猜。声明缺失时按 `desktop` 处理并在报告里注明。

## 6. 配对：按角色，不按选择器

样式比较最容易出假数字的地方。取"第一个同名元素"会产生看似真实的噪声——参考里的第一个按钮是侧边栏主 CTA（280×52），实现里的第一个按钮是页脚小按钮（98×30），差值报 `-185 / -22`，全是错的。

规则：
1. 两侧**各量一遍**，得到两份几何/样式清单；
2. 按角色配对：容器、行、控件、文本块，各自按出现顺序对齐；
3. 配不上的元素记为"未配对"，**不参与差值计算**，单独列出；
4. 未配对数量超过总量的 20% 时，样式维结论作废，只保留像素结论；
5. **图标内部不是布局**：`<svg>` 的子路径、圆、描边属于素材细节，不进入几何配对；图标只比较外框；
6. **亚像素复核**：几何按整数比较通过、但像素差异仍超容差时，必须把元素盒保留两位小数再比一次。整数量化会把 0.25px 的偏移抹平成"0 漂移"，而这点偏移足以让每个字形的栅格结果都不同。

实测：整数几何 0 漂移、像素差异 1.027%；查到标签盒 top 为 77.75 vs 78.00；修正 0.25px 后降到 0.337%，再修标题后降到 0.136%。**结论：亚像素偏移是真实成因，量化会把成因藏起来。**

## 7. 取证纪律

页源模式下，**禁止读取参考页的源文件**（HTML/CSS/JS）。只能通过渲染结果取证：截图、computed style、几何、可见行为。

理由很实际：读了源文件，任务就从"还原"变成了"复制"，而复制检验不出还原能力。这条纪律同时也是能力边界——能被证伪的结论才有价值。

禁止清单：
- 打开或抓取参考页的源码、源映射、构建产物；
- 复制参考页的样式表片段；
- 绕过登录、付费墙、反爬或访问限制。

## 8. 前置门：确定性

出任何结论前，先做自比较：同一页面连续渲染两次，像素差异必须为 **0.00%**、几何漂移必须为 **0**。

不成立时：环境不稳（字体未就绪、动画未停、随机数、时间戳、视口漂移），**禁止出结论**，判决直接 `UNVERIFIED`。

这一条由代码强制，且必须在每次运行的最前面执行，不允许跳过。

## 9. 环境能力探测与降级

浏览器不是必然可用。起不来（沙箱限制、未安装、端口被占）时：

1. 明确报告"无法渲染"，给出原因；
2. 降级为静态检查（源码层面的断言，如 emoji、图标、占位文案）；
3. 判决只能是 `UNVERIFIED`，**不得**因为静态检查全过就给 `READY`。

降级路径必须自动发生并写进报告，不许静默通过——静默通过是最坏的一种失败。

## 10. 收敛规则

改一轮必须遵守：

1. **一次只改一个高影响原因**，不做多点同时修改；
2. 每轮必须**同时**看像素与几何：像素说"更差了"，几何说"哪里错的"；
3. 差值排序固定：内容与状态 → 容器与网格 → 字体与换行 → 主要媒体 → 间距 → 颜色与材质 → 细节；
4. 两轮之内必须下降，否则回滚该轮并重新取证；
5. 达到"通过"后仍需再跑一轮确认不是偶然。

## 11. 文本抗锯齿的处理

中文字形在栅格化时的差异会让差异占比永远停在 1% 上下，把阈值变成摆设。

处理方式：
1. 从 DOM 取所有文本节点的包围盒，生成文本遮罩；
2. 遮罩内的小差异（≤ 噪声阈值）视为抗锯齿噪声，不计入判决；
3. 遮罩内的大差异（> 噪声阈值）说明文字真的错位、错字或字重不对，**必须计入**；
4. 报告必须同时输出三个数字：结构性差异、其中文本大偏移、其中被剔除的噪声；
5. 噪声占比超过 50% 时，说明字体或栅格化差异本身有问题，**先解决字体，不许靠遮罩过关**。

遮罩是用来区分"噪声"与"真实错位"的，不是用来把数字做小的。任何用遮罩让差异归零的做法都属于作弊。

### 11.1 字形栅格地板

同一段文字，宽度一致、位置一致、颜色一致，笔画覆盖的像素仍可能不同——这是字体栅格化的差异，不是实现缺陷。

判定方式：**文本区面积占比 与 差异贡献占比 的倍数**。文本通常只占卡片面积的 5–10%；若它贡献的差异超过面积占比的 3 倍，说明差异来自字形而非布局或颜色。

实测：文本区占面积 6.4%，贡献 48.3% 的差异（7.5×）。同一页面上页面源模式能追到 0.136%，图源模式停在 4.155%，差的就是这一层栅格。

处理原则：
1. 报告必须显式标注"字形栅格地板"，并给出面积占比、差异占比、倍数三个数字；
2. **不因此放宽阈值**。地板是解释，不是豁免；要豁免必须走"替代项"或人工声明，且记录在交接里；
3. 到达地板后继续调样式属于无效劳动，应停止并记录。

### 11.2 改字号之前必须先量字宽

字宽比对（`text-width.mjs`）给出每段文字的墨水包围盒宽度比值，并区分三种情况：

- 比值一致且接近 1 → 宽度没问题，差异来自位置或颜色，**不要动字号**；
- 比值等比偏离 → 字号或字族不同（不是字重）；
- 比值不一致 → 更像字重、字距或个别字符回退。

实测反例：在没有宽度证据时凭观感把表头 12px 改成 11px、得分 15px 改成 17px，差异从 4.876% 涨到 4.998%。补上字宽比对后，一次测量即定向，并发现真正原因是颜色而非字号。

### 11.3 地板声明（READY WITH DECLARED FLOOR）

图源模式天然停在字形栅格地板上。若无出口，这个最常用的场景永远拿不到通过结论。出口是**显式声明**，不是自动放宽。

成立条件（全部满足才给该判决）：

1. 视觉维不通过，且**唯一原因是像素差异超实质阈值**——几何漂移必须为 0；
2. 文本集中度超过阈值（默认 3 倍），即差异确实来自字形而非布局或颜色；
3. 规范维通过（检查项合格或已豁免）；
4. 调用方用 `--floor "<证据>"` 显式声明，证据必须可核（例如字宽比值、逐段取色结果）。

判决为 `READY WITH DECLARED FLOOR`，同时写入替代清单。声明为空、或任一条件不满足时，一律回到 `NOT READY`。

取舍是明确的：**宁可要一个带证据的显式豁免，也不要一个悄悄放水的阈值。** 前者在报告里留痕，后者会被滥用。
