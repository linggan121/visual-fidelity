# 视觉还原

把一份视觉参考变成可运行的前端代码，并证明它有多接近。**判决由工具给出，不由自我评价给出。**

## 规则

1. **先定参考形态**：只有图 = 图源模式，必须先用 `image-spec` 取证；能渲染 = 页面模式，可直接读 computed style。两者的证据强度不同，判决上限也不同。
2. **禁止读参考站点的源文件**。只看渲染结果与计算样式。读了源码，任务就从还原变成复制。
3. **改之前先量**。像素超标时按序排查：几何配对 → 差异归因 → 亚像素复核 → 字宽比对。不量就改等于猜。
4. **一轮只改一个高影响原因**，两轮之内差异必须下降，否则回滚该轮。
5. **没有证据不给结论**。缺截图、缺对比、环境不稳，一律 `UNVERIFIED`。

细节与阈值见 `protocol.md`（唯一规范来源）。

## 用法

在技能目录下执行（`node` 会自己起浏览器，不需要额外的 shell 脚本）：

```bash
# 结构取证（图源模式必做）
node image-spec.mjs --img 参考.png

# 一次完整对比：渲染 → 配对 → 归因 → 两维判决 → 报告
node run.mjs --ref 参考.png --impl 实现.html --width 1440 --root ".card"

# 页面参考（证据更强）
node run.mjs --ref 参考页.html --impl 实现.html --root ".card" --device touch

# 卡住时按序排查
node text-width.mjs --ref out/ref.png --impl out/impl.png        # 是字号、字重还是字族
node measure-text.mjs --ref 参考页 --impl 实现页 --sel ".label"    # 是亚像素偏移吗
```

产物写入 `out/<运行名>/`：`ref.png`、`impl.png`、`heatmap.png`、`geometry.md`、`attribution.md`、`report.md`。

环境变量（都可选）：
- `CDP_URL`：连接已启动的浏览器，而不是自己拉起
- `BROWSER_PATH`：指定 Edge/Chrome 可执行文件路径

## 判决

| 判决 | 含义 |
|---|---|
| `READY` | 视觉与规范都通过，无替代项 |
| `READY WITH SUBSTITUTIONS` | 通过，但有替代项或继承性豁免 |
| `READY WITH DECLARED FLOOR` | 差异集中在文本区且已声明地板证据；几何零漂移、规范通过 |
| `NOT READY` | 视觉或规范不通过，或任一几何漂移 |
| `UNVERIFIED` | 证据缺失或环境不稳，不得下结论 |

差异高度集中在文本区（集中度 > 3×）时，报告会标注**字形栅格地板**——这是度量的下限，不是实现缺陷。要用这个状态通过，必须显式声明证据：

```bash
node run.mjs --ref 参考.png --impl 实现.html --root ".card" \
  --floor "字宽 30 区域比值 1.000；颜色逐段取样一致"
```

地板不能救几何漂移，也不能救检查项失败。

## 失败诊断

- **起不了浏览器**：`node` 会自己找 Edge/Chrome 并拉起。受限沙箱下 Chromium 无法创建命名管道，需要放宽权限；或用 `CDP_URL` 连接外部已启动的浏览器。起不来只能静态检查，判决为 `UNVERIFIED`。
- **差异卡在 1% 附近不动**：先查几何配对是否为 0 漂移，再做亚像素复核（元素盒保留两位小数）。实测过 0.25px 偏移让整页文字每个字形都不同。
- **差异卡在 4% 附近**：查归因是否集中于文本；若是，先跑 `text-width` 确认宽度，再查颜色，最后才考虑字号。实测在没有宽度证据时凭观感调字号，差异反而上升。
- **`--inherit` / `--floor` 参数报错**：`--inherit` 用 `"检查项:证据"`，`--floor` 直接给证据文本。证据必须能从图上读出来（例如取色值、宽度比值）。
